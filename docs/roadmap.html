01注意事項與適用邊界

「砍掉 98% 註解」有前提
Grok Bot 的目錄結構、型別系統與 API 命名本身夠清楚。老專案若充滿歷史黑盒與隱式狀態機，一刀切只會讓人與 Agent 一起抓瞎。重點是禁止「辯護型過程註解」，保留領域不變量說明。
TLA+ / Lean 只用在高價值鏈路
Agent 降低了撰寫門檻，但建模與解釋仍很耗 Token（參考 70% 驗證開銷）。中小團隊先把 Lint + 依賴邊界 + CLI 截圖自檢跑起來，CP 值遠高於全面形式化驗證。
不要做的事
  • Agent 一犯錯就往 CLAUDE.md / AGENTS.md 加一行
  • 在壞的內迴圈上接自動化觸發器
  • 讓寫碼的 Agent 自己審自己的 PR
  • 用 Prompt 寫流程說明書微操 Agent
  • 犯一次錯就立規矩（要兩次）
一句話總結
護城河正從「自己手寫每一行」轉向「搭一套確定性環境，讓 Agent 很難寫出垃圾，並且能自己證明它是對的」。
