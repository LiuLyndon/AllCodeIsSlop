0114 條清單重點（依主題歸納）

以下為重點摘要，非逐條翻譯；原文請見 poteto 的推文。

A
用工具取代記憶

每發現一個問題就請 bot 寫成 Lint 規則，連註解都由 Lint 禁止（需要解釋就改命名或補測試）。熱路徑檔案用 .hot.ts 標示並禁止配置記憶體；首次下載超出預算時建置直接失敗。
對應原則：encode-lessons-in-structure。圖解見 演講 › 目錄即上下文。

B
用驗證取代人工試玩

劇情、過場與遊戲系統的狀態機用 TLA+ 驗證，每個主要系統一個形式化驗證技能。模擬完全確定，可從輸入重播；上傳高分時伺服器重播整局防作弊。bot 以 headless 方式試玩，依目標存活率調整難度。
對應原則：prove-it-works、build-the-lever。

C
一切都是程式碼

引擎大多自製（three.js 只負責 3D 繪製）。沒有音訊檔，音樂與音效在瀏覽器即時合成；像素美術也由程式碼繪製並在建置時打包。Agent 因此能讀、能改、能 diff、能驗證，沒有黑盒素材。

D
明確的體驗門檻

可直接在 X 貼文內遊玩，目標是中階手機上數百個敵人仍維持 60 fps；支援多語系與依戰績動態產生的分享圖，不同區域的音樂無縫銜接。
對應原則：experience-first、explain-the-number。

E
速度來自上面四點

業餘專案 4 天合入約 1,150 個 PR。不是靠更多人力，而是窄 PR 加上每一步都可自動驗證（sequence-verifiable-units）。

02可以直接借用的 6 個做法

① 每個 Bug → 一條 Lint
修完 Bug 順手請 Agent 寫規則並附修正指引，規則先在原 Bug 上報紅。
② 檔名傳遞約束
*.hot.ts、*.server.ts、*.pure.ts… 再用 Lint 依檔名套規則。
③ 預算進 CI
bundle 大小、首屏時間、FPS 門檻，超標就讓建置失敗。
④ 讓系統可重播
確定性 / 事件溯源讓 Bug 可重現，Agent 能自行重播驗證。
⑤ 資產程式碼化
能用程式碼表達的資產（圖示、音效、設定）就別用二進位檔，Agent 才看得懂、改得動。
⑥ 自動化實跑調校
headless bot / E2E 腳本取代人工試玩，產出可重跑的證據。
