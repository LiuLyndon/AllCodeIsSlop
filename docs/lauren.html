人物與信任非 CS 出身，怎麼一步步放手給 Agent

從 13 歲自學網頁、讀金融、創業失敗，到 React 團隊與 Grok Bot。這一頁補上她的背景、「信任曲線」，以及 Benny 到 Grok Bot 的由來。

成長路徑信任曲線Benny → Grok Bot個人習慣

00成長路徑：沒讀過 CS，一步步走到 React 團隊

她大學讀的是金融，第一次覺得寫程式好玩，是在金融建模課寫 Excel VBA 巨集。每一份工作幾乎都來自公開分享時認識的人。

01信任是一點點攢出來的

PR 數量從來不是目標；她要的是「自己不在場時，Agent 也能交出高品質成果」。9/21 她發佈影片分享「上個月往生產環境合入 2,500 個 PR」，到 10 月個人單月已是 3,127 個。

她對 Agent 的看法
Agent 就像永遠處在失憶狀態的新進員工：記不住你說過什麼，也不會真的學會新東西，只能靠 rules、skill、工具與長期記憶去近似。
瓶頸在驗證
剛進 Cursor 時她每天手動用 Chrome DevTools 抓效能 trace、拍記憶體快照，煩到開始想「我們明明有 Agent」。Agent 寫得很快，難的是確認它寫對了，於是她開始寫驗證類 skill，讓 Agent 自己跑 App、抓 trace、找熱點。
每次介入都是訊號
8 月她寫道：每次出手糾正 Agent，都該想辦法讓這類糾正永遠不再需要。這就是 pstack /correct 的起點。
程式碼庫就是記憶
10 月她補充：Agent 反覆犯的錯若不變成約束，就會像病毒一樣一直被複製下去（對照演講的「雜草擴散」）。

信任曲線：為什麼沒辦法從 5 個直接跳到 100 個

02「懶」是很實在的動力：從 Benny 到 Grok Bot

她自稱是很懶的人：Cursor 的 Bug 回報太多，她只想把它們全部修掉，最好在她睡覺時就修好。

03個人層面：今天就能開始的習慣

技術面的做法（先定義驗證、只跑 1–5 個、同錯往上提一層修）已合併進 優化步驟；這裡只列個人習慣。

邊學邊公開
她能上 EmberConf，靠的是學 Ember 時寫的部落格與推文。不必等學成才發，學到哪寫到哪，別人才有機會找到你。
列一張害怕清單
她把「不害怕＝太舒適」當訊號。寫下最近因為怕而沒做的一兩件事（投稿、發長文、去面試），挑一件去試。
從最煩的重複工作下手，先自己走一遍
Benny 起於 Bug 太多；驗證 skill 起於手動抓了很久的 trace。親手走通流程，才知道該怎麼讓 Agent 做、怎樣算做對。
每年問自己一次：還興奮嗎？
她當經理前就和自己約好每年重新評估，不是夢想中的工作就回頭。用 AI 也一樣，給自己定一個回看的時間。
10/8 她只發了兩行字，大意是：你應該更有野心，遠比現在更有野心。
