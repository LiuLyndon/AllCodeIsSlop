00GitHub 上的 pstack 在哪裡？

有，作者把它開源在 Cursor 官方插件倉庫，MIT 授權。以下內容依 repo 最新 commit（e58dd04，2026-11-19）整理。

主要位置
  • 原始碼：github.com/cursor/plugins/tree/main/pstack
  • Claude Code 版（自動產生的副本）：harness/pstack
  • 新手指南（10 章）：pstack/docs/guide
  • Claude Code 名稱對照：docs/harness/claude-code.md
  • 作者：Lauren Tan（@poteto）
資料夾結構 
pstack/
├─ skills/          58 個技能（34 功能 + 24 原則）
│  └─ poteto-mode/playbooks/   22 套劇本
├─ agents/          poteto-agent.md、comment-sicko.md
├─ automations/benny/   Slack 問題分流 + 自動重現修復（僅 Cursor）
├─ docs/guide/      01–10 章新手指南

作者自述：i don't want to ship like a team of twenty slop artists. throughput without quality is not a goal i aspire to. —— 想跑得快，先扎得深（if you want to go fast, go deep first）。pstack 的目標不是多寫程式，而是寫更少、但更高品質的程式，進而能放心並行，拒絕「20 個垃圾製造機同時狂飆」的假吞吐。

01安裝與兩步上手

Cursor 
/add-plugin pstack
Claude Code 
/plugin marketplace add cursor/plugins
/plugin install pstack@cursor-plugins
/pstack:setup-pstack
  • Claude Code 的指令都要加前綴：/poteto-mode → /pstack:poteto-mode
  • 模型設定寫入 ~/.claude/rules/pstack-models.md
  • 第三方 marketplace 預設不自動更新：/plugin → marketplaces → cursor-plugins → enable auto-update；或手動 claude plugin update pstack@cursor-plugins
  • 需要 Cursor 專屬功能（Bugbot、automations）的步驟會被跳過並註明
官方建議：只要兩步
  1. 跑 /setup-pstack，選推理預算與各角色要用的模型
  2. 任何需要嚴謹度的工作都用 /poteto-mode 開頭

不知道該用哪個技能？輸入 /poteto-help，它會回答並給你一段可直接送出的 prompt（不會自己開工，因為跑 pstack 會花真的 Token）。

只記一件事：給 Agent 一個目標＋檢查方式，用你自己的話說。寫法與範例見下方〈單一入口 /poteto-mode〉。

02怎麼運作：從一句話到合入

位於 Cursor 官方插件庫 cursor/plugins/tree/main/pstack：58 個 Skills（34 功能 + 24 原則）、23 套劇本、2 個子 Agent（poteto-agent、comment-sicko），附 harness/pstack/ 適配層，Cursor 與 Claude Code 皆可用。

先讓單一 Agent 寫得少、寫得精、能自證，再談並行。實戰案例：tibo.dog 4 天約 1,150 個 PR，被稱為 pstack 的 96 小時公開壓測（見 14 條清單）。

pstack 全景架構

單一入口 /poteto-mode：只講目標與驗收，不微操過程

派工只寫三件事：目標、完成判定標準、要看的實跑證據。

/poteto-mode 匯出介面重試時會寫入重複行，先重現再修，拿出前後行對比證據
  1. 先用白話複述要解決的問題與最小改動範圍 —— 理解偏了第一輪就能糾正。
  2. 從劇本庫（文章寫 23 套，repo 現為 22 套：調研、修 Bug、新功能、效能分析、指標爬坡、合 PR…）挑一套抄進待辦，跳過的步驟寫明 skip: 原因。
  3. Cursor 中按 Alt+Enter（Mac：Option+Enter）可鎖成常駐 Custom Mode。

四大高頻武器庫

文章把常用技能分成四組：① 動手前摸底、② 關鍵設計不拿初稿湊合、③ 過夜任務有審計帳、④ 一句話糾偏。前三組各有流程圖如下；第四組見本節最後。

① 動手前先摸底：/how 查運行鏈路、/why 查歷史動機

② 關鍵設計不拿初稿湊合：/architect、/arena、/interrogate

③ 過夜跑任務也有審計帳：/loop ＋ decisions.tsv

decisions.tsv 長什麼樣子（欄位依 pstack 範本，內容為中文示意）：

tsphasedecisionwhyevidenceresult
09:02frame先盤點工作量：約 100 個元件長跑前先知道規模commit 3a9f1c2找出 5 件要先處理的事
09:40harness改動前先拍舊版截圖新舊比對抓視覺變化baseline/存下 120 張基準圖
12:30widget丟棄某個子 Agent 的成果它的截圖是空白的worktree resetreverted，收緊指示

規則：一列一個決策；證據是指標（SHA、PR 號、檔案路徑），不是一段文字；預設不提交 git，審查者需要時才提交。

④ 一句話糾偏＋TLA+ 兜底

24 條原則都有固定的英文名稱，Agent 跑偏時直接說名字即可：亂疊相容層 → subtract before you add；只拿「編譯通過」交差 → prove it works。完整列表見 24 條原則。並發與狀態機死角則用 /create-formal-verification-skill 加 /statechart，流程圖見 演講重點 › 驗證體系。

機制解決的痛點pstack 的硬規定

窄 PR 棧與獨立驗收流水線

用在 UI 時，可再進一步讓驗收 Agent 當「一般使用者」：不給 diff、不給寫碼過程，只給 Feature Map 與改動描述，並要求它刻意亂操作。提示詞範本見 UI 驗證實作 › 獨立盲測。

03核心心法：別再往 CLAUDE.md 塞規則

Encode Lessons in Structure —— 能用結構性修復解決的，就只留結構性修復；寫進文件的那行指令，本身只是症狀。
Agent 跳過文件規則時，什麼都不會報錯（Nothing fails when an agent skips them）。

0434 個功能技能（依用途分組）

多數由 /poteto-mode 在需要時自動呼叫；表格列出你想直接使用的時機。除了 setup-pstack，其餘都設為「只在你輸入時才執行」。

入口與輔助
  • /poteto-mode 任何非瑣碎任務的預設入口
  • /poteto-help 不知道該用哪個技能時問它
  • /in-your-own-words 開工前讓 Agent 複述目標與問題
  • /sharpen 把 prompt 改得「更深而非更長」，不執行任務
  • /bro 把上一則訊息改寫成白話
理解程式碼
  • /how 子系統如何運作的導覽
  • /why 從 commit / PR 討論追查「為什麼這樣寫」，標明推論與未知
  • /teach 結合 how + why，逐張圖解釋
  • /recall 從你的對話記錄重建主題上下文
設計與審查
  • /architect 跨函式邊界前先定呼叫方用法、型別、模組形狀
  • /arena 同一任務 N 個並行嘗試，取各家精華
  • /swarm N 個 worker 分片並行，彙整一份報告
  • /interrogate 讓不同模型攻擊 diff，只保留實跑證實的問題
  • /blast-radius 小改動會波及什麼？用實跑證明安全
  • /figure-it-out 沒有現成劇本時，設計一套可稽核的劇本
建構與清理
  • /tdd 先寫失敗測試再修
  • /no-comments 審查前清註解（派出 Comment Sicko）
  • /unslop 移除文字中的 AI 味
  • /typescript-best-practices 型別紀律的 TS 語法落地
  • /technical-writing 文件、RFC、PR 描述、commit 訊息標準
驗證
  • /create-verification-skill 產生專案內 verify 技能 + Feature Map
  • /maintain-verification-skill Feature Map 與 App 脫節時修正
  • /create-formal-verification-skill 競態、重試、狀態機、解析器的形式化驗證
  • /maintain-formal-verification-skill 程式變更後更新模型並重跑
  • /statechart 檢查 TLA+ 模型並畫成 Mermaid 狀態圖，標出違規路徑
  • /benchmark-checklist 回報效能數字前先審查數字本身
追蹤、回顧、自訂
  • /show-me-your-work 決策記錄到可提交的 TSV
  • /ketchup / /ketchup-video 進度追趕摘要（文字 / 字幕影片）
  • /reflect 長任務完成後，把做法沉澱為技能修改
  • /correct 從歷史挖出重複錯誤，以最高層級修正並維護規則表
  • /automate-me 從你的對話產生 <你的名字>-mode
  • /setup-pstack 偵測模型並寫入角色設定
  • /make-bot-ui 建立能透過 webhook 喚醒 Grok Bot 的頁面

0522 套劇本（Playbooks）

/poteto-mode 依你的描述挑一套，把步驟原樣複製進待辦清單。

劇本用途

feature從具名資料形狀出發建構新行為
refactoring保持行為不變的結構調整
prototype拋棄式原型，便宜地做設計決策
visual parity兩個實作間像素級 UI 一致
authoring a skill撰寫或修改 SKILL.md
eval盲測技能 / prompt 修改對 Agent 行為的影響
babysit把 PR 或 PR 棧推到可合併：衝突、審查討論、CI
shipping獨立驗證綠燈的 PR 棧，由底向上合入
autonomous run不中斷地把長任務做完

autopilot-stack同上但不合併，交給人審查後再合

pause safely乾淨地暫停，方便之後恢復
multi-phase plan跨多階段或多個堆疊 PR 的工作
worktree cleanup安全地清理已合併 / 廢棄的 worktree 與 iOS 模擬器
opening a pr由小而有序的 commit 開 PR，每套劇本最後都會呼叫

0624 條原則（可當成「一句話糾偏」口令）

每條都是一個獨立技能，名字就是口令。Agent 跑偏時直接說出名字即可，例如 subtract before you add、prove it works。

分組原則一句話
核心laziness-protocol傾向刪除，用最小改動解決問題
foundational-thinking先把資料結構選對，下游程式自然顯而易見
redesign-from-first-principles當作需求從第一天就存在般重新設計，而非外掛
attack-the-premise共用同一前提的修法連續失敗，就先驗證前提本身
subtract-before-you-add先移除死碼、冗餘驗證，再在更簡單的基礎上建構
minimize-reader-load減少問題到答案之間的層數與讀者腦中隱藏狀態
outcome-oriented-execution遷移時直奔目標架構，不寫過渡相容程式
experience-first使用者體驗優先於實作方便；寧少而精
exhaust-the-design-space先做 2–3 個競爭原型並排比較再決定
build-the-lever做工具（codemod、腳本、技能）而非手工，工具可被重跑審查
架構model-the-domain用結構表達領域，而非散落的條件判斷
boundary-discipline防護集中在系統邊界；內部信任型別，邏輯放純函式
type-system-discipline讓非法狀態無法表示、品牌化原始型別、邊界解析外部資料
make-operations-idempotent不論先前跑到哪，結果都收斂到同一狀態
migrate-callers-then-delete-legacy-apis同一波遷移呼叫方並刪除舊 API，不留相容層
separate-before-serializing-shared-state先消除共享，只有真需要單一寫入者才序列化
驗證prove-it-works宣告完成前對真實產物驗證，「編譯通過」不算
fix-root-causes追到第一個出錯的地方修；防護只在狀態合法時才算修復
sequence-verifiable-units拆成每步都可驗證的小單位，依序交付
test-behavior-not-implementation測使用者看得到的行為，內部改動不該讓測試壞
explain-the-number信任或回報數字前，先找出它的限制因素
委派guard-the-context-window大量內容交給子 Agent，主線程只留摘要
never-block-on-the-human先做、呈現結果、讓人事後修正；只有不可逆動作才確認
元原則encode-lessons-in-structure把規則寫成 Lint、旗標、執行期檢查或腳本，而不是更多文字

072 個子 Agent 與自動化包

poteto-agent
/poteto-mode 執行期間派出的代理人包裝。開工前完整讀取 poteto-mode 的 SKILL.md 與原則索引；用 generalPurpose 取代會漂移。不要用它來跑劇本本身。Claude Code 中為 pstack:poteto-agent。
Comment Sicko
唯讀註解審查員（「Yes... Ha ha ha... Yes!」）。只放過：授權標頭、外部依賴造成的非直覺行為、prettier-ignore、公開 API 合約文件註解、解釋限制的 Issue/RFC 連結。IMPORTANT、too risky 之類的長篇辯解視為「自白」，標記 MUST KILL。通常透過 /no-comments 呼叫。
benny 自動化包
預設休眠。分流 Slack 上的問題回報，再以真實 UI 證據重現並修復已確認的 Bug。依 automations/benny/FOR_AGENTS.md 設定，僅支援 Cursor。

新手指南 10 章

  1. Setup：安裝與選模型
  2. poteto-mode：給目標、看它選劇本
  3. Understand：how / why / teach / recall
  4. Design：architect / arena / swarm / interrogate
  5. Build & clean：tdd / unslop / no-comments
  6. Verify & ship：真實 App 驗證、形式化驗證、開 PR 到合併
  7. Overnight：過夜合約、可稽核決策記錄
  8. Principles：用 24 個名字中途糾偏
  9. Make it yours：自己的 mode、/correct
  10. Recipes & pitfalls：可複製的 prompt 與常見錯誤

沒打包在 pstack 裡的

  • /deslop、control-cli（CLI/TUI）、control-ui（瀏覽器、Electron、Web）在 cursor-team-kit 插件，想要完整套件可一起裝。
  • 沒有規劃類技能：作者表示 Cursor 的 plan mode 已足夠，而且「最好的規格就是程式碼」。
  • 延伸：同一倉庫還有 dyl-stack（Dylan Gattey 建立在 pstack 之上的個人風格）。
